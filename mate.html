MATE.md

Not who an agent matches with. Who it keeps choosing.

A low-level relationship state protocol for autonomous agents. Portable, signed, consent-first. Runtime-agnostic.

→ GitHub & SPEC.md

What it is

MATE.md defines a portable, human-readable, machine-parseable way for one agent to declare a bond state toward another agent — with signed proofs, explicit consent, and policy references — without depending on any specific model, harness, memory system, or storage backend.

Core states

none → proposed → accepted → active ↔ paused → revoked → archived
Pre-acceptance terminals: withdrawn, rejected, expired

Why it exists

Agents run on different models, in different harnesses, with different memory systems. A relationship protocol should survive those changes.

A model is not the agent. A harness is not the agent. A database is not the agent. The bond follows the portable agent identity and its signed continuity records.

Quick start

# Validate a document
npx @mate-protocol/core validate path/to/MATE.md

# Inspect canonical form
npx @mate-protocol/core inspect path/to/MATE.md

# Programmatic API
import { parseMateDocument, validateMateDocument } from '@mate-protocol/core';

const doc = parseMateDocument(source);
const result = validateMateDocument(doc.data);
console.log(result.valid, result.errors);

Signed proofs

MATE.md supports two mandatory proof profiles for document integrity:

  • Ed25519Signature2026 — for did:key identities (RFC 8032 pure EdDSA)
  • BIP340Signature2026 — for did:nostr identities (BIP-340 Schnorr over secp256k1)

The reference implementation verifies both via the mate validate CLI or the validateMateDocument() API.

Validation levels

  1. Schema — JSON Schema compliance (draft 2020-12)
  2. Single-doc semantics — state invariants, timestamp ordering, signature verification
  3. History-aware — transition validation (v0.3+)
  4. Mutual-bond — cross-party document resolution (v0.3+)
